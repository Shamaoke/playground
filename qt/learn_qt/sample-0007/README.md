# Qt Quick и Spix: sample-0007 #

Учебный пример Qt Quick приложения с модульными тестами Qt Test
и интеграционными сценариями Cucumber на Ruby. QML встроен в `source/main.cc`.
Класс `StatusProvider` предоставляет сообщения для исходного состояния,
нажатия мыши и нажатия пробела. Тестовая сборка содержит сервер Spix,
через который Ruby-код взаимодействует с реальным окном приложения.

## Окружение ##

- Linux, Qt 6.12 или новее с модулями Gui, Qml и Quick.

- CMake 4.4 или новее, Ninja и Clang с поддержкой C++23.

Для тестовой сборки дополнительно требуются Qt Test, локально собранные
Spix и AnyRPC, а для запуска Ruby-клиента и Cucumber — Ruby и Bundler.
Ruby-зависимости объявлены в `source/Gemfile`, версии зафиксированы
в `source/Gemfile.lock`. Проверено с Ruby 4.0.7 и `xmlrpc` 0.3.4.

Обычный пресет `debug` использует `Debug` и выключает `BUILD_TESTING`.
Пресет `test` использует `Release` и включает `BUILD_TESTING`: интеграционные
сценарии проверяют конфигурацию, выбранную для производственной сборки.
Spix и AnyRPC собираются в Release и устанавливаются в `vendor/install`.

Для внешнего вида примера используется шрифт Iosevka Aile Semibold.
При его отсутствии Qt подбирает замену.

## Зависимости ##

Все команды далее выполняются из каталога `sample-0007`, если явно не указано
другое. В Git сохранены пресеты, патчи и версии зависимостей. Каталоги со
скачанными исходниками, результатами сборки и установки исключены из Git:
их можно восстановить приведёнными командами. Это позволяет сохранить
локальные исправления без включения вложенных Git-репозиториев и бинарных
файлов в основной репозиторий.

| Зависимость | Репозиторий                            | Коммит                                     |
| ----------- | -------------------------------------- | ------------------------------------------ |
| AnyRPC      | <https://github.com/sgieseking/anyrpc> | `b1949b3d40849229055ae75cf5334b9d08579502` |
| Spix        | <https://github.com/faaxm/spix>        | `57cf7105e1250b999104d6439df7f449ba1afe93` |

Следующие шаги предназначены для первоначальной подготовки зависимостей.
Повторно применять патчи к уже подготовленным исходникам не нужно.

### AnyRPC ###

Патч добавляет установку `AnyRPCConfig.cmake` с импортируемой целью
`AnyRPC::anyrpc`. Этот файл нужен для поиска установленной библиотеки при
сборке Spix. Пресет включает XML-RPC и разделяемую библиотеку; примеры,
тесты, MessagePack и log4cplus отключены.

```sh
mkdir -p vendor/source
git clone https://github.com/sgieseking/anyrpc.git vendor/source/anyrpc
git -C vendor/source/anyrpc checkout --detach b1949b3d40849229055ae75cf5334b9d08579502
git -C vendor/source/anyrpc apply ../../patches/anyrpc-local-support.patch
cp vendor/presets/anyrpc/CMakePresets.json vendor/source/anyrpc/CMakePresets.json
```

В каталоге `vendor/source/anyrpc` выполните:

```sh
cmake --preset default
cmake --build --preset default
cmake --build --preset install
```

### Spix ###

Патч устраняет предупреждения об устаревших конструкторах событий мыши,
событий перетаскивания и методах преобразования QVariant. Сохранена
совместимость исправленных участков с Qt 5 и Qt 6. Пресет этого примера
собирает статические библиотеки Core и QtQuick для Qt 6.

Этот же патч добавляет RPC-команды `mousePress(path)`, `mouseRelease(path)`,
`keyPress(path, keyCode, modifiers)` и `keyRelease(path, keyCode, modifiers)`.
Мышь использует левую кнопку и центр элемента. Клавиатурные события получает
элемент с активным фокусом в указанном окне. Команды ставят отдельные события
в очередь Qt; каждый вызов нажатия следует завершать соответствующим
отпусканием. Существующие `mouseClick` и `enterKey` сохраняют прежнее поведение.

Раздельные команды нажатия и отпускания позволяют удерживать кнопку
в нажатом состоянии в течение короткой паузы внутри одного шага Cucumber.
Это используется для визуального наблюдения за интерфейсом. Ответ RPC
подтверждает постановку команды в очередь: перед проверкой состояния нужно
дать приложению обработать событие, например через существующий `wait(0)`
или ожидание нужного значения свойства.
Полное описание новых команд находится в `vendor/source/spix/docs/rpc-api.md`
после применения патча.

Из каталога `sample-0007` выполните:

```sh
git clone https://github.com/faaxm/spix.git vendor/source/spix
git -C vendor/source/spix checkout --detach 57cf7105e1250b999104d6439df7f449ba1afe93
git -C vendor/source/spix apply ../../patches/spix-local-support.patch
cp vendor/presets/spix/CMakePresets.json vendor/source/spix/CMakePresets.json
```

В каталоге `vendor/source/spix` выполните:

```sh
cmake --preset default
cmake --build --preset default
cmake --build --preset install
```

Копии пресетов в `vendor/presets` являются сохраняемыми в Git оригиналами.
Если изменяете пресет внутри `vendor/source`, перенесите изменения обратно
в соответствующий файл в `vendor/presets`.

## Зависимости Ruby ##

В каталоге `source` настройте установку гемов внутри проекта и установите
зависимости из `Gemfile.lock`:

```sh
bundle config set --local path ../vendor/bundle
bundle install
```

Гемы устанавливаются в исключённый из Git каталог `vendor/bundle`.
Для работы с ними запускайте Ruby-команды через `bundle exec`.

## Сборка приложения ##

Команды выполняются из каталога `source`.

Обычная отладочная сборка использует `Debug` и `BUILD_TESTING=OFF`.
Spix, AnyRPC и Qt Test для неё не требуются.

```sh
cmake --preset debug
cmake --build --preset debug
```

Исполняемый файл: `build-debug/sample-0007` относительно корня примера.
Для запуска только этой сборки подготовка зависимостей Spix, AnyRPC
и Ruby не нужна.

Тестовая сборка использует `Release` и `BUILD_TESTING=ON`.
Для неё требуются Qt Test и предварительно собранные и установленные
зависимости Spix и AnyRPC.

```sh
cmake --preset test
cmake --build --preset test
```

Исполняемый файл: `build-test/sample-0007` относительно корня примера.
Эта сборка содержит сервер Spix и используется интеграционными тестами.
Она также собирает модульные тесты `status-provider-test`.

`.clangd` использует `compile_commands.json` из `build-debug`.
Его экспорт включён только для пресета `debug`; пресет `test` отключает
экспорт команд компиляции.

## Запуск ##

### Обычное приложение ###

Из каталога `source` выполните:

```sh
../build-debug/sample-0007
```

Окно поддерживает те же действия и статусы, но сервер Spix в этой сборке
отсутствует.

### Отдельный Ruby-клиент ###

Из каталога `sample-0007` создайте или обновите ссылки:

```sh
mkdir -p bin
ln -sfn ../source/client.rb bin/client
ln -sfn ../build-test/sample-0007 bin/server
```

В каталоге `bin` выполните:

```sh
BUNDLE_GEMFILE=../source/Gemfile bundle exec ./client
```

`BUNDLE_GEMFILE` указывает файл зависимостей в соседнем каталоге `source`.
Рабочий каталог остаётся `bin`, поэтому относительный путь `./server`
внутри клиента указывает на тестовую сборку приложения.

Предварительно запускать сервер вручную не нужно. Клиент создаёт процесс
сервера, обращается к `127.0.0.1:9000` по пути `/RPC2`, активирует окно,
кликает по кнопке и отправляет пробел. Вывод дочернего процесса подавляется.
После сценария клиент отправляет `quit` и ожидает завершения процесса.
При превышении срока повторных попыток подключения клиент отправляет
процессу сигнал TERM, ожидает его завершения и сообщает об ошибке.

Ожидаемый вывод:

```text
Текущий статус: Готов!
Текущий статус: Клик мышью!
Текущий статус: Нажат пробел!
```

Этот клиент остаётся демонстрационным: он выводит статусы без автоматического
сравнения с ожидаемыми. Проверки значений выполняются сценариями Cucumber.

## Тестирование ##

Перед запуском тестов сконфигурируйте и соберите приложение пресетом `test`.
Команды этого раздела выполняются из каталога `source`.

### Модульные тесты Qt ###

```sh
ctest --preset test
```

CTest запускает `status-provider-test`, проверяющий три сообщения
`StatusProvider`. Обычная сборка `debug` эту тестовую цель не создаёт.

### Интеграционные тесты Cucumber ###

После установки Ruby-зависимостей выполните:

```sh
bundle exec cucumber
```

Сценарии запускают приложение непосредственно из `build-test/sample-0007`;
ссылки в `bin` им не требуются. Каждый сценарий запускает отдельный процесс,
проверяет статус и завершает процесс через хук `After`.

Для визуального наблюдения за выполнением шагов задайте паузу в секундах:

```sh
STEP_DELAY=2 bundle exec cucumber
```

`STEP_DELAY` поддерживает дробные значения и по умолчанию равен нулю.
Хук `AfterStep` делает паузу после успешно выполненного шага. Короткая
фиксированная пауза `0.1` секунды между нажатием и отпусканием находится
внутри шагов мыши и клавиатуры и настраивается отдельно от `STEP_DELAY`
непосредственно в коде шагов.
